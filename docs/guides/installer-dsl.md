# Web Installer & Dynamic Flashing DSL

The `nim-esphome/dsl/installer` module provides a declarative Nim DSL for generating interactive, single-page web installers with [ESP-Web-Tools](https://esphome.github.io/esp-web-tools/) and dynamic WebSerial flashing.

It enables developers to define user-customizable flashing forms (file uploads, dropdown selects, text inputs, checkboxes) and guarantees flash partition safety through automated ESP-IDF partition table calculation.

---

## The Problem: Custom Assets & Flash Collisions

When distributing embedded devices, end users often want to customize on-device assets at flash time—such as:

- Custom voice assistant audio feedback loops (e.g., custom sound effects while waiting for LLM response).
- Device configuration blobs or pre-shared keys.
- Custom display bitmaps or splash screens.

However, naive web flashing presents two major technical hurdles:

1. **Flash Partition Overlap Hazard**: Standard ESP-IDF 4MB dual-OTA partition layouts define:
   - `app0`: `0x10000` – `0x1D0000` (~1.8 MB)
   - `app1`: `0x1E0000` – `0x3B0000` (~1.8 MB)
   Flashing user assets at an arbitrary address (such as `0x380000`) directly corrupts `app1`! Any future wireless OTA update from Home Assistant will either overwrite the custom data or fail boot verification.
2. **Dynamic Manifest Requirement**: ESP-Web-Tools expects a static `manifest.json` describing firmware binary offsets. Flashing user-provided local files in the browser requires dynamically constructing partition manifests with in-memory `Blob` objects.

`nim-esphome` solves both problems declaratively.

## Quick Start Example

```nim
import nim_esphome/dsl

let satelliteInstaller = esphomeInstaller("voice-satellite"):
  installer.title = "Voice Satellite Web Installer"
  installer.chipFamily = "ESP32-S3"
  installer.description = "Flash verified voice satellite firmware and customize audio assets."
  installer.factoryBinPath = "firmware-factory.bin"

  # Define hardware board targets
  installer.addTarget(
    name = "Seeed ReSpeaker XVF3800",
    binPath = "firmware-factory.bin",
    chipFamily = "ESP32-S3",
    description = "4-mic array with hardware acoustic echo cancellation"
  )
  installer.addTarget(
    name = "Home Assistant Voice PE",
    binPath = "firmware-voice-pe.bin",
    chipFamily = "ESP32-S3",
    description = "Official Nabu Casa smart speaker satellite"
  )

  # Define custom file upload to a dedicated flash partition
  installer.addFileField(
    name = "custom_audio",
    label = "Custom Audio Loop (.wav)",
    accept = ".wav,audio/wav",
    partition = "sound_data",
    maxSize = 262144, # 256 KB
    description = "Custom PCM WAV audio loop played during voice processing"
  )

  # Text field with phonetic spelling guidance callout
  installer.addTextField(
    name = "wake_word_phrase",
    label = "Phonetic Wake Word Phrase",
    placeholder = "okay see three pee oh",
    calloutHtml = "Spell words phonetically (e.g., <code>ok c3p0</code> &rarr; <strong>okay see three pee oh</strong>).",
    description = "Phonetic representation used by the wake word model engine"
  )

  # Define firmware behavior configuration
  installer.addSelectField(
    name = "default_style",
    label = "Audio Feedback Style",
    options = @["Spinner", "Pulse", "Sonar", "Tick", "Silent"],
    defaultVal = "Spinner",
    description = "Default acoustic style when custom audio is not active"
  )

# 1. Output verified, collision-free partition table CSV for ESPHome
writeFile("partitions.csv", satelliteInstaller.generatePartitionsCsv(flashSizeMb = 4))

# 2. Output baseline ESP-Web-Tools manifest
writeFile("web/manifest.json", satelliteInstaller.generateManifest())

# 3. Output self-contained single-page web installer with dynamic WebSerial controller
writeFile("web/index.html", satelliteInstaller.generateHtml())
```

## Flash Partition Safety

The `generatePartitionsCsv(flashSizeMb: int)` function calculates safe offsets for OTA slots (`app0` and `app1`) and dedicated user data partitions:

### 4MB Flash Layout (`flashSizeMb = 4`)
- Both `app0` and `app1` are sized to **1.7MB** (`0x1B0000`), ending at `0x370000`.
- Custom user data partitions start safely at offset **`0x370000`**, leaving up to **576 KB** of non-volatile asset storage before the 4MB flash limit (`0x400000`).
- Over-the-air (OTA) updates from Home Assistant remain fully functional without overwriting user asset partitions.

```csv
# ESP-IDF Partition Table generated by nim-esphome installer DSL
# Name,   Type, SubType, Offset,   Size, Flags
nvs,      data, nvs,     0x9000,   0x5000,
otadata,  data, ota,     0xe000,   0x2000,
app0,     app,  ota_0,   0x10000,  0x1B0000,
app1,     app,  ota_1,   0x1C0000, 0x1B0000,
sound_data, data, 0x82,  0x370000, 0x040000,
```

### 8MB+ Flash Layout (`flashSizeMb = 8`)
- `app0` and `app1` are sized to **3.0MB** (`0x300000`), ending at `0x610000`.
- Custom user data partitions start at offset **`0x610000`**, providing almost 2MB of dedicated asset storage.

## Client-Side Dynamic Manifest Architecture

The generated `index.html` embeds a lightweight, reactive client-side JavaScript controller.

When the user selects a file (such as a custom sound loop or bitmap):
1. The client-side controller validates the file type and file size against `maxSize`.
2. It generates a local in-memory object URL via `URL.createObjectURL(file)`.
3. It constructs a new dynamic manifest combining the base factory firmware (offset `0x0`) and the uploaded file (at its partition offset, e.g. `0x370000`).
4. It attaches the dynamic manifest `Blob` directly to `<esp-web-install-button>`:

```javascript
const blob = new Blob([JSON.stringify(manifest)], { type: 'application/json' });
installBtn.manifest = URL.createObjectURL(blob);
```

When the user clicks **Install Firmware**, ESP-Web-Tools connects to the ESP32 over WebSerial and flashes both the base firmware and custom asset partition in one single operation.

## Supported Form Fields

| Field Kind | Helper | Description |
| :--- | :--- | :--- |
| **File Upload** | `addFileField` | Uploads local binary/audio assets and flashes to a partition offset. |
| **Dropdown Select** | `addSelectField` | Select option list for user preferences or profiles. |
| **Text Input** | `addTextField` | Text field for custom identifiers or device names. |
| **Numeric Input** | `addNumberField` | Bounded numeric input with min, max, and step validation. |
| **Checkbox** | `addCheckboxField` | Boolean toggle for enabling/disabling optional device features. |

## Integrating with ESPHome YAML

To instruct ESPHome to use the custom partition layout generated by `nim-esphome`, declare the partition table in your board package:

```yaml
esp32:
  board: esp32-s3-devkitc-1
  framework:
    type: esp-idf
    partitions: partitions.csv
```

In your Nim firmware code, you can read from the dedicated partition using ESP-IDF partition APIs or standard flash memory mappers to access the uploaded user assets directly.

## Hardware Considerations: ESP32-S3 Native USB & Improv Wi-Fi Serial

When building installers for ESP32-S3 boards with native USB (e.g. Seeed ReSpeaker Lite XVF3800, ESP32-S3-DevKitC-1 native USB port), the microcontroller uses its internal USB-Serial-JTAG controller rather than an external CP2102/CH340 USB-to-UART bridge.

### The Bootloader Quirk
1. When WebSerial flashes or erases the device, the chip enters and stays halted in the **ROM Bootloader**.
2. Because native USB does not have hardware RTS/DTR strapping reset circuits, software reset signals issued by browser flashers (`esp-web-tools` or `esptool-js`) cannot trigger a clean Power-On Reset.
3. Immediately after flashing completes, **the board is still in bootloader mode and ESPHome has not booted yet**.

### User Flow & Provisioning
- The board **must be power-cycled** (unplug and replug the USB-C cable) or have its hardware **RST** button tapped once after flashing.
- If a user attempts to click **Configure Wi-Fi** while still in the bootloader, the browser receives 0 serial bytes and displays:
  ```
  An error occurred. Improv Wi-Fi Serial not detected
  ```
- Once power-cycled, ESPHome performs a cold boot, initializes native USB, and starts `improv_serial` as well as its fallback AP (`Satellite Fallback Hotspot`). Clicking **Configure Wi-Fi** immediately detects Improv Serial and presents the Wi-Fi credentials prompt.

The `nim-esphome` installer DSL automatically includes this guidance in the on-page setup guide and the interactive post-install modal.
